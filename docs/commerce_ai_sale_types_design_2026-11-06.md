# commerce_ai 판매 유형 설계서 (직접판매·중개·구매대행)

2026-11-06 · Ason

## 요약

commerce_ai 의 모든 상품은 **판매 유형 5가지** 중 하나로 표시하고, 유형마다 판매 당사자·고지 문구·결제 위치·책임 범위를 다르게 다룬다. 전자상거래법상 판매자(통신판매업자)와 중개자(통신판매중개자)의 의무가 다르고, 2026-06-17 에는 자체 상품과 중개 상품의 구분 표시를 의무화하는 개정안이 발의됐다.

1. **직접판매** — 운영자가 소싱해 파는 상품. commerce_ai = 판매 당사자.
2. **중개(입점)** — 오프라인·온라인 판매업체가 올린 상품. commerce_ai = 중개자.
3. **구매대행** — 고객 주문을 받아 코스트코몰·Shopify 상점·아마존 등에서 대신 구매. 고객이 commerce_ai 에 대금을 내므로 판매 당사자에 가까운 책임을 전제로 설계.
4. **판매처 이동(제휴)** — 쿠팡 파트너스처럼 다른 몰로 보내고 수수료를 받는 상품 (구현됨).
5. **참고 정보** — 업체 제공 목록·해외 UCP 몰 등 비교·참고용 (구현됨).

이 문서는 설계용 정리이며 법률 자문이 아니다. 조항은 열어 본 원문·기사만 근거로 적었고, 원문을 확인하지 못한 내용은 **(미확인)** 으로 표시했다. 사업 개시 전 전문가 검토가 필요하다.

## 유형별 법적 지위·의무

판매 당사자가 누구인지와 대금을 누가 받는지가 책임을 가른다. 중개라도 commerce_ai 가 주문 접수나 결제를 맡으면 판매자 의무를 대신 이행해야 한다.

**구매대행의 핵심 제약.** 자가사용 면세 한도는 물품가 미화 150달러(미국산 200달러)이고, 건강기능식품은 1인 6병까지 자가사용으로 인정된다. 자가사용으로 감면받은 물품을 재판매하면 밀수입죄·관세포탈로 처벌될 수 있다(관세청, 2026-01-08). 따라서 구매대행은 **주문별로 고객 명의로 통관**하는 구조여야 하고, 미리 사 두고 파는 방식은 구매대행이 아니라 수입 판매(직접판매)로 다뤄야 한다.

**발의된 개정안.** 2026-06-17 발의안은 자체 상품·중개 상품 구분 표시 의무(법 제20조제1항 개정, 위반 시 과태료)와 청약 접수·대금 수령 중 생긴 손해에 대한 플랫폼 배상책임(고의·과실 없음을 입증하면 면책)을 담았다. 통과·시행일은 확인하지 못했지만, 이 설계는 처음부터 구분 표시를 전제로 한다 ([MTN, 2026-06-17](https://news.mtn.co.kr/news-detail/2026061711262527736)).

## 구매대행 원천: 코스트코몰·Shopify·아마존

세 원천 중 공식 데이터 경로가 바로 있는 곳은 **Shopify(UCP)** 뿐이다. 아마존은 제휴(판매처 이동)용 API 라 구매대행 가격 산정에 쓸 수 있는지 약관 확인이 필요하고, 코스트코몰은 공식 API 를 찾지 못했다. 페이지 수집(스크래핑)은 프로젝트 원칙상 쓰지 않는다.

| 원천 | 데이터 경로 | 확인된 조건 | 미확인·위험 | 1차 판단 |
| --- | --- | --- | --- | --- |
| Shopify 상점 | UCP catalog.search (구현·실제 검색 확인, 2026-11-05 allbirds) | 상점이 판매자 기록상 주체(MoR). 카탈로그 가격은 확약이 아니고 결제 화면이 기준. 에이전트 구매는 구매자가 건별 승인 ([Forkast, 2026-10-14](https://forkast.news/shopify-is-widening-the-catalog-door-to-personal-agents-the-sign-off-stays-human/)) | 상점별 재판매·구매대행 허용 여부, 한국 배송 여부(안 되면 배송대행지 필요), 달러 가격·환율 | **첫 구매대행 원천** — 등록부에 상점별 허락·배송 조건을 적은 곳만 |

코스트코몰 구매대행은 국내 거래라 통관은 없지만, 문서의 다른 구매대행과 같은 판매 당사자 책임(가격 구성 표시·환불·식품 취급)을 진다. 해외 원천(Shopify·아마존)은 여기에 통관·면세 한도·수입식품 규정이 더해진다.

## 화면 표시 규칙

모든 상품 카드는 판매 유형 배지와 판매 당사자 이름을 한 줄로 보여 준다. 법정 고지는 사이트 첫 화면과 주문(청약) 확인 화면 두 곳에 둔다.

| 유형 | 카드 배지 | 카드·상세의 판매자 줄 | 주문 확인 화면 고지 |
| --- | --- | --- | --- |
| 직접판매 | trendguide 직접 판매 | 판매자: (운영 사업자 상호) · 사업자 정보 보기 | 판매자 상호·연락처·청약철회 조건 |
| 중개(입점) | 입점 판매 | 판매자: ○○상회 · trendguide 는 통신판매중개자 | "trendguide 는 통신판매중개자로서 통신판매의 당사자가 아닙니다. 상품·거래에 관한 의무와 책임은 판매자에게 있습니다." (판매자 표시와 같거나 큰 글씨) + 판매자 정보 |
| 구매대행 | 구매대행 · (국가) | 구매처: ○○(원 판매처) · 판매·배송 책임: trendguide | 가격 구성표(물품가·수수료·배송비·예상 관부가세), "고객님 명의 자가사용 통관", 반품비·취소 가능 시점, 예상 도착일 |
| 판매처 이동(제휴) | 제휴 링크 · 수수료 제공 | 판매처: 쿠팡 등 · 구매는 판매처에서 | 주문 화면 없음 (판매처 이동). 응답 맨 위 '광고' 표시 (구현됨) |
| 참고 정보 | 참고용 | 출처·확인 시각 | 주문 없음 |

- **초기 화면**: 중개 상품이 하나라도 있으면 하단이 아닌 눈에 띄는 위치에 중개자 고지와 운영자 신원정보를 둔다 (시행규칙 제11조의2).
- **한 화면에 여러 유형이 섞일 때**: 배지로만 구분하고 순서는 같은 선택 규칙을 따른다 (순위 공정성 절).
- **AI 에이전트(MCP·UCP) 응답**: 같은 판매 유형·판매 당사자·고지 문구를 필드로 내보낸다. 외부 화면 표시는 보장하지 못한다는 점도 응답에 적는다 (현재 쿠팡 고지와 같은 방식).

## 데이터 구조

기존 공통 계약(commerce.v1)의 `Offer` 에 판매 유형과 판매 당사자를 더하고, 구매대행에만 가격 구성·통관·품목 제한을 붙인다. 기존 `link_type`(affiliate 등)은 유지하고 `sale_type` 을 새로 둔다.

```python
class SellerOfRecord(BaseModel):            # 판매 당사자 (중개면 입점 업체, 직접판매·구매대행이면 운영 사업자)
    name: str                              # 상호
    representative: str | None             # 대표자
    business_no: str | None                # 사업자등록번호
    mail_order_no: str | None              # 통신판매업 신고번호
    contact: str | None                    # 연락처 (전화·이메일)
    address: str | None

class PriceBreakdown(BaseModel):           # 구매대행: 고객이 낼 총액의 구성 (원 단위 정수, 모르면 None)
    goods_krw: int | None                  # 물품가 (외화면 환산값 + 환율·기준시각)
    fee_krw: int | None                    # 구매대행 수수료
    intl_shipping_krw: int | None
    domestic_shipping_krw: int | None
    est_duty_vat_krw: int | None           # 예상 관부가세 (추정임을 화면에 표시)
    fx: dict | None                        # {'currency':'USD','rate':..., 'as_of':...}

class Offer(BaseModel):                    # 기존 필드에 추가
    sale_type: Literal['direct', 'marketplace', 'purchase_agent', 'referral', 'reference']
    seller_of_record: SellerOfRecord | None
    checkout_at: Literal['commerce_ai', 'seller_site', 'none']   # 대금 받는 곳 → 제20조의3 판단
    source: dict | None                    # 구매대행: {'merchant','country','url','channel':'ucp|api|manual'}
    price_breakdown: PriceBreakdown | None
    restrictions: list[str]                # 'food_import_registration', 'self_use_limit', 'cold_chain' ...
```

| 항목 | 저장 위치 | 규칙 |
| --- | --- | --- |
| 개인통관고유부호 | 주문 데이터(상품 모델에 두지 않음) | 암호화 저장, 통관 완료 후 정해진 기간에 파기, 접근 기록. 보관 기간은 법적 확인 후 확정 |
| 구매대행 가격 | Offer.price_breakdown | 표시가 = 항목 합. 환율·기준 시각 표시. 원화 비교(100g당·가성비)에는 넣지 않고 별도 목록 |
| 판매 당사자 | 입점 업체 등록부(허락 기록부와 같은 방식) | 없으면 중개 상품을 공개하지 않음 |
| 품목 제한 | Offer.restrictions | 주문 전 확인. 식품 수입 구매대행은 영업등록 확인 전 비활성 |

**UCP 매핑.** 직접판매·구매대행은 commerce_ai 가 Business(판매자 기록상 주체)로 판매자 프로필을 내고, 중개 상품은 UCP variant 의 `seller` 칸에 실제 판매자를 넣는다. 판매자 역할의 프로필·결제는 외부 몰을 조회하는 현재 플랫폼 역할(p40~p42)과 별도 설계다.

## 순위 공정성·테스트 원칙

직접판매 상품은 순위에서 우대하지 않는다. 자기 상품 우대는 플랫폼 규제의 주요 쟁점이고, 지금도 '제휴 여부는 순위에 영향 없음'을 테스트로 보장하고 있다.

- **불변 테스트**: 같은 후보의 `sale_type` 을 바꿔도 선택·순서·사유가 같아야 한다 (직접판매 ↔ 중개 ↔ 제휴).
- **비교 범위**: 원화 단일 가격이 확정된 상품만 가격·100g당 비교에 넣는다. 구매대행(환율·예상 세금 포함)과 참고 정보는 별도 목록.
- **고지 테스트**: 중개 상품이 있는 응답에는 반드시 중개자 고지가, 구매대행 주문 화면에는 반드시 가격 구성표가 있어야 한다.
- **공개 차단 테스트**: 판매 당사자 정보가 없는 중개 상품, 영업등록 확인 전 식품 구매대행 상품은 화면·MCP·UCP 어디에도 나가지 않는다.
- **기록**: 응답 provenance 에 유형별 개수를 남겨, 직접판매 비중이 얼마나 노출되는지 관리자 화면에서 볼 수 있게 한다.

## 개발 순서

판매 유형 필드부터 넣고, 화면 공개는 유형별 확인이 끝난 순서로 연다. 각 단계는 기존처럼 백업·테스트·기본 꺼짐으로 진행한다.

1. **판매 유형 필드** — `sale_type`·`seller_of_record`·`checkout_at` 추가. 기존 상품은 쿠팡=판매처 이동, 업체 목록·UCP=참고로 채움. 순위 불변·고지 테스트.
2. **화면 표시** — 카드 배지·판매자 줄, 초기 화면 운영자 정보·중개자 고지 자리. MCP·UCP 응답에 같은 필드.
3. **입점(중개) 등록부** — 판매자 정보·허락·상품 등록. 상세페이지 제작 모듈과 연결. 결제는 판매자 사이트 이동부터 (제20조의3 책임 회피).
4. **구매대행 견적** — Shopify(UCP) 상점 원천으로 가격 구성표·환율·면세 한도 안내만 (주문 없는 견적 화면). 식품은 영업등록 확인 전 제외.
5. **아마존 제휴** — 어소시에이트 가입·Creators API 자격 확보 후 판매처 이동 유형으로 (조회 시각 표시·캐시 1시간·고지 문구).
6. **주문·결제** — 직접판매·구매대행 주문, PG 계약, 개인통관고유부호 보안 저장, 배송 단계(우체국·택배·포워딩 연계 대비). 확인 항목이 끝난 뒤.
7. **판매자 쪽 UCP** — 직접판매·입점 상품을 UCP 판매자 프로필·원격 MCP 로 공개.
