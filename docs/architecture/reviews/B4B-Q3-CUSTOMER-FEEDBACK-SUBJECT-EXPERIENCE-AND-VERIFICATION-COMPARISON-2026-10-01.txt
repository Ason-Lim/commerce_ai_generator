B4-B — Q3 고객 피드백의 평가 대상·경험 연결·검증 범위 대조
작성일: 2026-10-01 (Asia/Seoul)
성격: 운영 전 문서 연구 / 합성 사례 대조 / 채택·구현 결정 아님

1. 한정 연구 결과

Q3 문서 대조를 완료했다. 기존 R4는 평가 대상, 출처, 작성자 참조, 경험 상관, 경험 검증, 고객 진술, 운영 증거와 진위·남용 검토를 이미 구분한다. 이 의미 경계와 미해결 의존성을 재사용할 근거가 있다.
provenance와 scoped correlation은 일부 보존 기반이다. 그러나 출처 관계와 generic evidence state만으로 피드백 전용 검증 의미가 충족되지는 않는다. 실제 작성자 경험·피드백 사실 검증 및 현재 생산 계약의 충분성은 입증하지 않았다.
external_evidence_provider_*의 직접 대상은 외부 데이터 제공자 평가다. 이를 물류사 고객 피드백으로 전용할 수 있다고 확정하지 않는다. 아래 재사용은 의미·보존 의무의 후보이며 그대로 쓸 수 있는 생산 모듈 판정이 아니다.
Architecture Need=UNRESOLVED. 이번 자료로 새 owner·schema 또는 새 구조의 필요성을 확정하지 않는다. 과거 R4의 NEW/REQUIRES_NEW_CONTRACT 분류도 현재 구현 부재나 즉시 신설 승인으로 승격하지 않는다.
PM1/PM2 완료와 실제 E1/E2 보류를 유지한다. 기존 R1–R6 및 DQ1–DQ7 완료 기반을 재개하지 않는다.
실제 피드백 자료를 수집하거나 작성자·고객을 식별하지 않았다. 아래 사례는 모두 합성 문서 추론이며 실제 리뷰·운송·고객 검증 결과가 아니다. 저장소 쓰기·커밋·푸시, 생산 코드·schema·DB·업체 연동은 수행하지 않았다.

2. Q3 질문과 구분

피드백이 누구의 어떤 서비스·경험을 평가하는지 확인 가능한가?
출처의 확인 표시는 무엇을 검증했으며 그 근거·시점·범위가 무엇인가?
작성자 참조와 실제 경험을 연결할 근거가 있는가?
고객 진술과 운영 자료가 일치·상충·미확인일 때 원래 진술과 별도 근거를 보존할 수 있는가?

평가 대상: 리뷰가 가리키는 물류사·서비스·구간 또는 접점에 관한 주장. source의 subject 참조만으로 법인·계정·실제 수행자를 인증하지 않는다.
증거 출처: 리뷰를 보고·전달한 플랫폼 또는 원천. 작성자와 별개이며, 출처를 알아도 작성자 경험은 미확인일 수 있다.
작성자 참조: 출처가 제공한 bounded author/customer 참조. canonical 고객 identity 또는 경험의 증명이 아니다.
경험 연결: 주문·요청·shipment·piece·package·tracking·고객 접점 등과의 상관 근거. 연결 자체는 작성자의 해당 서비스 이용이나 평가 적격성을 증명하지 않는다.
경험 검증: 누가 무엇을 어떤 근거로 확인했는지에 대한 한정 주장. 물류서비스 경험의 확인과 주문 확인·계정 확인·리뷰 초대는 서로 대체하지 않는다.
고객 진술: 만족·불만·지연·파손 등의 고객이 보고한 내용. 그대로 운영 사실·물류사 귀책·책임 또는 성과가 되지 않는다.
운영 대조: 별도 사건 자료와 진술의 동일 대상·사건·시각을 비교하는 검토. 운영 자료와 연결돼도 리뷰 원문을 운영 이벤트로 바꾸지 않는다.
진위·남용: 중복·조작·spam 등 검토의 범위와 근거. 경험 검증·진술 사실·긍정/부정과 별개다.

위 항목은 독립적인 연구 질문이다. 하나의 verified/unverified 값이나 trust 점수로 압축하지 않는다. 경험이 확인됐지만 사건 설명은 미확인일 수 있고, 출처·경험 연결이 있으면서 진술과 운영 보고가 상충할 수 있다.
미검증 != 거짓 != 부정 리뷰 != 검증 실패. 특정 경험 검증이 실패했다고 진술 전체가 거짓이거나 제공자 품질이 낮다고 판정하지 않는다.

3. 연구 검토 기준 — 생산 필드·enum·상태 전이 아님

F1 대상·차원: 평가된 업체·서비스·구간·접점과 무엇을 평가했는지. 상품 만족·판매자 응대·플랫폼 편의·배송 경험을 분리한다. 혼합 리뷰는 확인된 문장·주장의 범위만 연결한다.
F2 출처·보고 관계: 원문·source record·플랫폼·보고자·provenance와 source-to-subject 관계. third-party라는 label은 독립성·정확성·권한을 증명하지 않는다.
F3 작성자·역할: 출처 소유 opaque author 참조와 해당 경험에서의 역할 근거. 송하인·수하인·구매자·대리인 등 관계가 필요하면 확인하되 모든 물류서비스 경험을 구매 경험으로 제한하지 않는다. 실명·법적 identity를 임의 생성하거나 요구하지 않는다.
F4 경험 상관: 주문·요청·단위·서비스 접점의 관계와 issuer·범위. tracking 문자열 또는 주문 ID의 존재만으로 작성자 경험을 인증하지 않는다.
F5 경험 적격성: 작성자·평가 대상·서비스·단위·접점의 연결이 해당 검증 목적에 충분한지. 다른 주문·다른 구간·다른 물류사로 확대하지 않는다.
F6 확인 주장: 검증자·검증 방법·근거·시각·확인된 대상과 미확인 범위. 플랫폼 badge의 의미 근거가 없으면 플랫폼이 표시한 주장으로만 보존한다.
F7 시간: 경험 시각, 제출·보고 시각, 수집 시각 및 적용 가능한 효력 시각을 구분한다. retrieval/effective time으로 결측 경험·제출 시각을 채우지 않는다.
F8 진술·척도: 원문, 평가 차원, rating 범위·단위·missing/unknown/not-applicable 의미. 상품 별점과 물류사 평점을 동일시하지 않는다. 수치 0이 의미 있는 값인지는 해당 척도로 확인한다.
F9 운영 대조: Q1의 사건·단위·시간·약속 근거와 고객 진술을 별도 연결한다. 대조 결과가 지지·상충·불충분 중 무엇인지 그 정확한 주장 범위를 남긴다.
F10 진위·남용: 검토 주체·근거·중복 관계·상태와 불확실성. 익명·미검증·부정적 내용만으로 사기·spam을 판정하지 않는다.
F11 수정·삭제·분쟁: 원문과 변경의 추적 범위, 현재 사용 가능한 버전, 삭제·이용 제한 및 분쟁 상태. 수정은 독립 경험 추가가 아니다. 삭제는 내용 거짓·문제 해결의 증명이 아니다.
F12 모집단·이용 범위: 누구에게 피드백 기회가 있었고 어떤 접점·초대·수집 경로만 포함됐는지와 이용 허용 목적. 피드백 제공자 목록을 전체 고객·운송 모집단으로 확대하지 않는다.

이 기준은 필요한 근거와 금지된 추론을 구체화한다. 실제 고객 경험 확인 절차·허용 검증자·개인정보 정책·피드백 척도·남용 정책·가중치·집계 방법론을 채택하지 않는다.

4. 기존 R4의 검증 구분 대조

V0 Source Preserved: 출처 보존. 작성자·경험·진위·진술의 사실은 확정되지 않는다.
V1 Author Reference Preserved: 작성자 참조 보존 후보. canonical 고객 identity·경험 검증은 확정되지 않는다.
V2 Experience Correlation Preserved: 배송·tracking·요청·서비스 상관 보존. 작성자 이용·적격성·진술 사실은 확정되지 않는다.
V3 Verified Experience: R4에서 NOT_ESTABLISHED. 실제 별도 권한 근거 필요. 경험 검증이 긍정 피드백·진위·진술 전체의 사실을 뜻하지 않는다.
V4 Customer Statement Preserved: 고객의 보고 진술. 운영 사실·귀책·책임·성과로 승격하지 않는다.
V5 Operational Corroboration: 별도 운영 증거의 상관 대조. 원래 피드백과 운영 자료를 구분한다.
V6 Performance / Recommendation Use: 기존 R4 OUT_OF_SCOPE. 업체 점수·순위·추천·선택으로 이어지지 않는다.

기존 문서의 ladder label은 연구 구분이다. 자동 승급 순서·신뢰 점수 또는 운영 enum으로 채택하지 않는다. V4 진술은 V3 경험 검증이 없어도 진술로 구분할 수 있으며 V5의 일부 대조가 V3의 작성자 경험 권한을 대신하지 않는다.

5. 현재 확인한 계약의 재사용 범위

F1/F2: R4 section 6의 opaque evaluation-subject와 provenance 재사용 경계. ExternalEvidenceProviderEvaluationSubject는 canonical provider·법인·계정·선택 업체를 확정하지 않는다.
대조: 출처와 대상 참조의 구분은 재사용 후보다. 이 소스의 외부 데이터 제공자라는 subject 의미를 물류사 고객 피드백 대상으로 변경 없이 쓰는 충분성은 입증되지 않았다.

F2/F6/F10: ExternalEvidenceProviderEvaluationSourceRelationship 및 EvidenceState.
대조: SUBJECT_SUPPLIED/THIRD_PARTY/INTERNAL_OBSERVATION/UNKNOWN은 출처와 대상의 관계다. THIRD_PARTY는 독립 검증, INTERNAL_OBSERVATION은 실제 물류서비스 관측 완료를 뜻하지 않는다. generic evidence state는 경험·진위 검증 상태가 아니다.

F3/F4/F5: R4 sections 7/8와 R4-U1/U2/U3; 기존 source-owned logistics correlation.
대조: 참조와 상관 보존은 가능하다. 작성자의 실제 서비스 경험, 경험 검증 권한과 최종 eligibility rule은 기존 미해결 의존성이다. 새 canonical 고객 owner를 정하지 않는다.

F7: R4 section 9와 R4-U4, EvidenceProvenance의 수집 및 효력 근거.
대조: retrieval time은 재사용 가능하다. feedback submission/experience time 의미는 별도 근거가 필요하다. 소스 generic time 또는 metadata가 있다는 사실만으로 전용 시간 계약을 충족하지 않는다.

F8: R4 sections 10/11/12와 R4-U5/U6/U7/U8.
대조: 물류사 차원·척도·자유 진술·사건 주장에 전용 의미가 필요하다는 기존 의존성이 있다. external_evidence_provider_evaluation.py의 데이터 제공자 평가 차원을 배송 속도·고객 만족 차원으로 재해석하지 않는다. value를 담을 수 있다는 것만으로 피드백 계약 충분성을 입증하지 않는다.

F6/F9/F10: R4 sections 13/14와 R4-U9/U10/U17.
대조: 경험 검증·진위·운영 사실의 분리는 기존 연구로 확인됐다. 검증 정책·남용 판단·운영 사실 bridge는 미해결 또는 범위 밖이다. 인증된 출처 하나로 모든 판단을 해결하지 않는다.

F11/F12: provenance 및 정정 이력의 공통 의무, R4-U10/U11–U16과 Q2의 누락·중복·관측 창 구분.
대조: 추적 가능한 출처·변경을 유지할 근거는 있다. 리뷰 전용 수정·삭제·분쟁 집행과 이용 권한, 대표성·표본·가중치의 현재 생산 충분성은 미검증이다.

충분성 A — 의미 및 의존성 보존: 기존 R4를 재사용할 근거 있음.
충분성 B — 실제 경험·검증·적용 근거: 실제 자료 없음 / 미확인.
충분성 C — 전용 생산 계약과 저장·갱신·소비: 이번 검증 없음.
일부 generic 기반의 존재를 전체 충분성으로 승격하지 않는다. 반대로 미검증을 현재 저장소의 구현 부재로 단정하지 않는다.

6. 합성 반례 대조 — 실행 테스트·실제 리뷰 아님

U01 플랫폼 URL과 원문만 있음: 출처·진술 보존. 작성자 경험·대상 identity·내용 사실은 별도 미확인. F1–F6.
U02 주문 확인 badge만 있음: 표시의 정확한 확인 범위를 검토. 해당 물류사·구간 경험 또는 지연 원인의 검증으로 확대하지 않는다. F4/F6.
U03 리뷰에 tracking 번호만 있음: 상관 주장 보존. 작성자가 해당 서비스를 경험했음을 인증하지 않는다. F3/F4/F5.
U04 익명 수하인이 서비스 불편을 보고: 수하인 경험 관계와 검증 근거를 검토. 익명이라는 이유만으로 거짓·spam으로 분류하지 않는다. F3/F10.
U05 상품 품질·판매자 응대·배송이 한 리뷰에 혼합: 각 주장 대상·범위를 구분. 전체 별점을 물류사 품질로 옮기지 않는다. F1/F8.
U06 경험이 한정 검증됐고 '늦었다'고 진술: 경험 검증은 보존. 약속·발생 시각·사건 적격성 없이는 정규 지연·귀책을 확정하지 않는다. F6/F9.
U07 고객은 '늦었다', tracking은 예정 시간 내 delivered: 만족 표현과 서비스 약속을 구분. 동일 대상·사건·약속 기준을 확인하기 전 진술이 거짓이라고 판정하지 않는다. F8/F9.
U08 실제 지연 사건이 별도 대조됐으나 작성자 연결 없음: 사건 대조와 작성자의 경험 검증을 각각 보존. 운영 자료가 V3의 권한을 대신하지 않는다. F3/F5/F9.
U09 같은 리뷰가 두 플랫폼에서 재전달: 원문·source record·작성 및 경험 관계를 확인. 독립 경험 둘로 세지 않는다. F10/F12.
U10 작성자가 별점·진술을 수정: 현재 버전과 변경 근거를 구분. 새 고객 경험 표본으로 추가하지 않는다. F11.
U11 리뷰가 삭제됐다는 자료만 있음: 삭제 상태·이용 근거 검토. 거짓·문제 해결·부정 피드백 없음으로 변환하지 않는다. F11.
U12 고객 피드백 또는 rating이 없음: 없음·미확인·해당 없음 구분. 별점 0·나쁜 업체·좋은 업체를 만들지 않는다. F8 및 R4-U16.
U13 데이터 공급자가 SUBJECT_SUPPLIED/THIRD_PARTY 자료를 전달: 데이터 source와 평가 대상의 관계만 보존. 고객 검증·독립성·물류사 신뢰로 승격하지 않는다. F2/F6.
U14 고객 상담 접점에 리뷰가 연결됐으나 운송 단위 없음: 상담 경험의 연결 범위만 보존. 실제 pickup·배송 완료 경험으로 확대하지 않는다. F4/F5.
U15 긍정 고객에게만 초대된 자료라는 근거가 있음: 해당 모집·수집 범위를 보존. 전체 고객·운송을 대표한다고 판단하지 않는다. F12/Q2.
U16 경험 시간 없고 수집 시간만 있음: 수집 시각만 보존. 과거 배송 기간·provider 서비스 변경 시점에 경험을 임의 귀속하지 않는다. F7.

16개 사례는 기존 의미 경계와 의존성에 연결됐다. 이 결과는 운영 시스템의 테스트 통과나 실제 고객 진술 검증이 아니다. 진술을 물류사 성과·품질 점수로 전환하지 않았으며 실제 리뷰·개인정보·별점은 수집하지 않았다.
