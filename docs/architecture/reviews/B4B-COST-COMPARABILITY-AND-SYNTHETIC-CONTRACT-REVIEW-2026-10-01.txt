3. 비용 비교 전에 필요한 축 — 연구 질문, 생산 필드 채택 아님

각 가격 주장에 다음을 확인한다.
- 지급자·수취자 및 각 역할. 수수료의 명칭만으로 거래 방향을 정하지 않는다.
- 작업 범위: 집화, 배송, 분류, 보관, 소비자 수령, 또는 여러 작업의 묶음.
- 서비스·지역·접수처·요일·중량·규격 등 적용 조건.
- 산정 단위: 물품당, 정차/방문당, 묶음당, 기간당 등 원문에 제시된 단위.
- 기본료·추가료·최소요금·세금·기금의 포함 관계 및 부과 조건.
- 금액·통화, 조건 적용 시점, 만료·개정.
- 주장 종류: 보도된 협의안, 공개 안내 요금, 예상치, 실제 견적, 실제 정산.
- 원문 출처·발행자·권한 근거·자료의 완전성과 unknown.

비교 후보를 만들려면 비교 목적을 먼저 정한다.
고객이 지불할 총비용을 비교하는 목적에는 고객 청구 요금과 그 적용 조건이 필요하다.
기사 수당과 플랫폼 소비자 요금은 서로 다른 목적의 값이므로 같은 가격 순위에 넣지 않는다.
주장 종류·작업 범위·산정 단위·조건 차이가 남으면 동일 기준 비교는 보류한다.
동일 기준으로 환산하려면 물량·방문 횟수·중량 등 입력과 환산 가정을 별도로 명시한다.
총액에 이미 포함된 분류비를 다시 더하지 않는다. 누락 금액을 0원으로 간주하지 않는다.
견적의 기간 총액을 개별 거래에 배분한 계산은 출처 소유 견적과 별도 파생값으로 표시한다.
해당 비교 기준은 이번 연구의 소비 질문이며 정식 비교 알고리즘 채택이 아니다.

4. 가상 사례 대조 — 아래 요청·제공자·참조·수량·시간은 전부 합성

S1. 다른 거래 방향의 금액
입력: 제공자 X의 기사 정산 참고값과 제공자 Y의 고객 청구 참고값만 있음.
위험: 낮은 숫자를 저렴한 고객 견적으로 표시.
보존: 참고값의 거래 방향·범위·주장 종류·출처를 유지. 실제 M4 견적으로 승격하지 않음.
대조 결과: 공통 provenance/scope 및 M4 의미 구분으로 혼동을 피할 문서 근거가 있음.
비교 소비 경로가 이를 실제 강제하는지는 미검증. 두 값의 고객 가격 순위는 판단 보류.

S2. 묶음 총액과 건당 금액
입력: 가상 견적 X는 방문 1회·묶음 10개 총액, Y는 물품당 금액. 방문 조건은 미제시.
위험: X 총액을 10으로 나눈 값을 어떤 물량에도 적용되는 건당 요금으로 표시.
보존: X의 묶음·방문·물량 조건을 M4 원문 조건으로 유지. 나눗셈은 별도 가정 계산.
대조 결과: 원견적의 조건 보존은 M4로 대응 가능. 같은 조건의 총비용 비교는 추가 입력 필요.
최소 방문료·추가 방문료가 확인되지 않았으면 비교 총액을 확정하지 않음.

S3. 일부 단위만 수락
입력: 가상 요청 R1은 단위 U1·U2의 수거 요청. 응답 P1은 U1만 명시적으로 수락.
위험: R1 전체가 수락됐다고 표시하거나 U2를 거절로 처리.
보존: M5 배정 범위 U1·U2와 응답 범위 U1을 분리. U2는 응답 근거 미확인.
대조 결과: 기존 exact scope/unknown 보존 의무와 대응됨. 전량 수락·전량 요금은 확정 불가.
수락 단위가 줄면 견적 금액도 자동 감소한다는 규칙은 만들지 않음.

S4. 견적 변경 후 이전 버전 수락
입력: 합성 Q1 이후 Q2 발행. P1은 Q1을 명시적으로 참조하며 Q2 수락 증거는 없음.
위험: 최신 견적 Q2 금액을 P1의 수락 조건으로 덮어쓰기.
보존: M4 Q1/Q2의 버전·효력·철회와 M5 P1의 정확한 참조를 유지.
대조 결과: 기존 lineage 의무와 대응됨. 어떤 조건이 유효한 약속인지는 적용 합의 없이는 미확정.
최신 자료가 있다는 사실과 최신 조건을 수락했다는 사실을 구분함.

S5. 취소와 재예약
입력: 합성 R1/P1 예약 후 취소 요청 C1, 이어 새 R2/P2 예약. C1 처리 응답은 없음.
위험: R2 생성만으로 R1 취소 완료·위약금 없음·이중 청구 없음 확정.
보존: 취소 요청·취소 응답·새 예약의 각 주장과 이전/새 참조를 M5 lineage로 연결.
대조 결과: 요청과 응답 구분으로 대응됨. R1 취소 상태와 청구 영향은 각각 unknown.
취소요금 조건은 M4 또는 적용 합의 출처로, 실제 청구는 별도 정산 증거로 검토함.

S6. 조건 충돌과 도착 시각
입력: 합성 Q1은 14–16시 조건. P1은 예약 생성과 ready time만 반환.
이후 제공자 보고 이벤트가 하나 있으나 사건의 의미·범위가 불명확함.
위험: 예약 생성으로 시간대 보장 수락을 추론하고 이벤트를 픽업 완료로 사용.
보존: M4 시간 조건, M5 예약 응답, 원천 관측을 각각 분리.
대조 결과: 의미 분리는 기존 의무와 대응됨. 시간 약속 수락과 실제 준수는 미확정.
관측 이력 책임과의 연결 및 사건 해석 근거 없이 SLA 성공·실패를 계산하지 않음.

5. 이번 대조의 결과와 한계

6개 합성 사례를 기존 의미 의무와 문서로 대조했다. 코드 실행 테스트 결과가 아니다.
범위·출처·주장 종류·시점·unknown·개정 연결을 보존하면 위 잘못된 승격을 피할 수 있다.
이번 사례에서 새 의미 구조의 필요성을 입증하지 못했다.
이는 모든 비용 계약을 기존 모델이 충분히 표현한다는 보편적 증명이 아니다.
가격 비교 소비 경로의 강제 규칙, 비용 산식·환산·정산 모델은 구현·채택을 검증하지 않았다.
원문 가격을 보존하는 책임과 비교 가능성·파생 계산을 판단하는 책임은 구분한다.
M4는 출처 소유 견적 의미, M5는 배정 및 별도 제공자 응답 의미를 유지한다.
이번 비용 연구가 Recommendation 점수·자동 선택 또는 새 canonical owner를 정하지 않는다.

6. 남은 연구 질문과 다음 실행

운영 이전에도 가능한 다음 문서 연구:
공개 요금 안내의 실제 부과 조건(중량·지역·방문·추가료·취소·효력)을
각 원출처별로 정리하고, 비교 목적별로 공통 항목과 미확정 항목을 대조한다.
같은 범위의 소비자 운임끼리 비교 가능한지부터 검토하며 기사 수당과 혼합하지 않는다.
참고자료의 누락을 새 schema 필요성으로 자동 전환하지 않는다.

운영 증거 확보 이후:
동일 요청의 실제 quote/request/인증된 response/적용 합의를 접수해 E1/E2 검토에 재진입.
그때 실제 정보 손실이나 소비 오류가 확인되면 기존 계약 재사용·보완 대안을 먼저 대조.
필요성 판단 자료를 00_1에 반환하며, 구현 채택과 구분한다.

현재: Architecture Need UNRESOLVED / PM1·PM2 완료 유지.
이 보고서는 새 연구 산출물이며 승인된 이전 두 문서 커밋 범위에 포함되지 않는다.
추가 저장소 수정·커밋·푸시·업체 연동·실제 거래는 수행하지 않았다.
