## 고정 원칙 (모든 단계)
- 사업 지위: **통신판매중개자로 시작**. 다만 지위는 선언이 아니라 **실제 역할**로 정해지므로, 기능을 추가할 때마다 아래 조건을 다시 확인합니다.
  - 상품이 누구 것인가(셀러 / commerce_ai), 주문을 누가 접수하는가, 대금을 누가 받는가, 청약철회·환불을 누가 처리하는가.
  - 셀러 상품 + 셀러가 대금 수령 = 중개자. commerce_ai가 대금을 먼저 받으면 결제대금 수령 중개자(제20조의3, 7단계 검토). 중개자가 청약 접수·대금 수령·배송 등 판매자 업무를 직접 하면 그 업무에 대한 책임이 따로 생김(전자상거래법 해당 조문 확인). 직접 매입 판매는 통신판매업자(보류).
  - GPT Instant Checkout·구글 UCP 체크아웃·Google Pay를 써도 OpenAI·구글은 판매자가 아님. AI 결제는 국내 미지원이라 지금은 쓰지 않음(UCP는 카탈로그 노출만).
- 셀러 유형: 직접 재고 셀러 + **정식 위탁판매 셀러**(공급사와 위탁 계약, 공급사 직접 배송) 허용. **소매몰 차익거래(쿠팡·네이버에서 사서 되팔기)는 commerce_ai와 셀러 모두 불허**.
- 결제: **1단계는 셀러 쪽 결제**(스마트스토어·자사몰, commerce_ai는 대금을 받지 않음). **2단계 자체 결제**는 거래 규모를 본 뒤 국내 PG + 지급대행·파트너 정산으로 (법률 검토 후). Stripe는 한국 사업자 가입 불가.
- 수익: 쿠팡 파트너스 제휴 수수료 + **셀러 월 이용료(정기 구독)**. 판매 수수료는 자체 결제를 연 뒤 재검토.
- 카테고리: **식품 우선**. 로드맵 완료 후 다음 카테고리 추천 (후보: 주방·조리도구 → 생활용품 → 화장품은 역직구와 함께).
- CS: **분야별 AI CS, 사람 관여 최소화**. 이용자별 창구 3개(고객·셀러 센터·B2B) 안에서 AI가 분야를 판단해 처리. 운영자는 '사람이 반드시 맡는 일'(식품 안전, 법적 분쟁의 처리 방안, 개인정보 요구·유출, 셀러 입점 승인·정지·해지, 이용료 환불·예외, 계정 예외 복구, B2B 가격·납기 확정·제출, 위급 신호, AI 규칙 변경 승인·주간 검수)만 함. AI는 환불·보상·제재 면제·가격 확정을 하지 않음.
- **별도 연구 흐름은 추천에 바로 합치지 않음**: 해외배송 last mile 증거 연구와 B4-B 배송 공급자 평가 연구의 결과는 추천 점수·순위나 자동 배정에 곧바로 넣지 않습니다. 넣으려면 별도 결정(권한)이 필요합니다.
- 페이지 스크래핑 금지, 제휴 여부는 순위에 반영하지 않음, 근거 없는 가격·품질 단정 금지, 모든 가격에 확인 시각.
- 외부 API 수치(호출 제한·페이지 크기·처리 시간)는 **확정값이 아니라 검증 항목**. 실제 계정의 응답 헤더·권한으로 확인하고 측정값을 기록.
- 개인정보: 최소 정보 SSO, 데이터 흐름별 국외 이전 확인, 로컬 모델에도 접근 권한·로그 최소화 적용. 개인정보가 오가는 CS 분야는 로컬 모델에서만 처리. 주문자 정보를 공급사에 넘길 때는 셀러의 수탁자로서 위탁 계약·최소 항목·전송 기록·보존 후 파기.
- 커밋에 실제 키가 든 `.env`·백업 파일 포함 금지.

## 1단계 검사 항목 (넘어가는 기준)
- **순위 불변의 기준점**: 처음 기준은 main `1926036`이었으나, 1단계 진행 중 **사용자가 승인한 순위 변경**(아래 '순위 기준점 이력')이 이어졌습니다. 순위 불변 검사는 '가장 최근에 승인된 기준점' 대비로 하고, 승인된 순위 변경은 별도의 전후 비교와 '변동이 그 변경으로 설명되는가'로 검증합니다. 표시만 바꾸는 작업(문구·화면)은 항상 직전 기준점 대비 순서·후보 불변이어야 합니다.
- **엔진 순위와 최종 표시 순위 모두 확인**: 기존 비교는 엔진 정렬 단계까지만 했으므로 `main.py`·`explain.choose` 이후 화면에 나가는 최종 순위도 비교합니다.
- `rating_score_usable`의 세 경우(값 없음·거짓·참)가 각각 맞게 표시되고 점수에 들어가지 않음.
- 비교 불가 상품은 비교 불가 사유가 표시되고 가격 우위 문구가 나오지 않음.
- 가격 확인 시각이 없는 상품은 "확인 시각 없음"으로 표시되고 가격 단정 문구가 나오지 않음.
- 설명값(`explain_score_inputs()`)으로 다시 계산한 점수가 실제 점수와 일치.
- **Mac에서 전체 테스트 재실행**(0단계 기준선 대비 실패 증가 없음) 결과를 단계 문서에 기록.
- **노출 기록 조사 보고**: `impression_logger.py`가 있다는 것만으로 검증된 노출 분모가 생기지는 않습니다. 어떤 경로(API 응답·화면 렌더링·클릭)에서 기록되는지, 기록이 빠지는 경우와 누락률을 조사해 보고합니다. 실제 화면 표시와 연결된 노출 확인(누가 생산하고 누가 확인하는가)은 이 보고를 보고 **별도로 결정**하며, 1단계에서는 기록 방식을 바꾸지 않습니다.
- 범위 밖: 고객 화면 노출, 새 산식, 노출 기록 수정.

## 2단계 상세: 트렌드 리포트 MCP 도구 (선택 항목, 2026-11-10 사용자 결정)
- 목적: AI 에이전트가 commerce_ai의 **승인된 트렌드 리포트**를 직접 읽게 함. UCP는 상품·결제 규격이라 글(리포트)을 담지 않으므로, 리포트는 구조화 데이터·사이트맵 + MCP 도구로 내놓고 UCP는 5단계 입점 셀러 상품에만 씀.
- 위치: 기존 MCP 서버(`app/mcp_adapter`, 도구 `food_search_products`·`food_get_recipe`)에 읽기 전용 도구 추가 — 예: `food_trend_reports`(목록·검색), `food_trend_report`(한 편 읽기).
- 응답에 담는 것: 승인된 글만, 제목·요약·본문(또는 원문 링크)·작성/승인 일시·출처, 관련 상품은 **링크 목록**(가격은 넣지 않고 "판매처에서 확인", 넣는다면 확인 시각과 함께), 쿠팡 파트너스 등 **광고·제휴 고지 문구 그대로**.
- 넣지 않는 것: 미승인·검토 중 글, 오래된 가격으로 만든 가격 우위 문구, 개인정보, 클릭 추적용 내부 링크 외의 추적 값.
- 검사: 웹 페이지와 같은 정책 검사(미승인 인용·오래된 가격·광고 표시 누락 차단)를 도구 응답에도 적용하는 테스트. 기존 MCP 도구처럼 읽기 전용 표시(read-only annotation).
- 시작 조건: 2단계 `/trends/...` 게시·검토 대기열이 먼저 동작해야 함(승인 상태가 있어야 '승인된 글만'을 지킬 수 있음). 외부 공개 범위(로컬 MCP만 / 원격 MCP 공개)는 6단계 공개 결정과 함께.

## 4~6단계 상세: 분야별 AI CS
- 창구: 고객 채팅(로그인 없이도 사용) / 셀러 센터 채팅(자기 업체 데이터만) / B2B 문의. 분야별로 채팅창을 따로 만들지 않음.
- 분야: 상품·추천, 쿠팡 제휴, 입점 셀러 주문·배송, 위탁판매 배송 예외, 해외 직구·역직구, 계정 복구, 셀러 문의, B2B. 분야마다 참고 자료·쓸 수 있는 도구(조회 / 접수)·넘길 대상을 따로 정함.
- 자동 처리: 확신이 낮으면 답을 만들지 않고 티켓으로. 티켓도 AI가 셀러 전달·추가 자료 요청으로 처리하고, 사람 필수 항목이거나 기한을 넘길 때만 운영자에게.
- 사람이 반드시 맡는 일과 기한: 식품 안전(당일, AI는 노출 즉시 임시 중지·1399 안내) / 법적 분쟁의 처리 방안(10영업일, AI는 3영업일 경과 자동 통지·초안) / 개인정보 열람·삭제·유출·외부 제공 요청(법정 기한, 유출은 즉시) / 셀러 입점 최종 승인(3영업일)·정지·해지·차익거래 판정 / 이용료 환불·감면·예외(5영업일) / 계정 예외 복구·셀러·운영자 계정 복구(3영업일) / B2B 가격·납기 확정·제출 / 위급 신호(즉시) / AI 규칙·참고 자료 변경 승인, 분야별 주간 샘플 검수(주 1회).
- 셀러가 정해 둔 자동 규칙(예: 미출고 취소 자동 승인)은 AI가 셀러 결정으로 처리. 운영자 관여 아님.
- **AI 실행 권한 4단계** (도구 권한과 테스트를 이 구분으로 정함):

| 권한 | AI가 하는 일 | 예 | 도구 권한 | 검사(테스트) |
|---|---|---|---|---|
| ① 접수 | 문의·요청을 기록하고 분야·기한을 붙임 | 환불 요청 티켓 생성, 3/10영업일 추적 시작 | 티켓 쓰기만 | 접수 기록·기한이 남는지 |
| ② 초안 작성 | 답변·통지·처리 방안 초안 | 분쟁 처리 방안 초안, 셀러 전달 문안 | 초안 저장만(발송·확정 없음) | 초안이 확정 상태로 바뀌지 않는지 |
| ③ 승인된 규칙 실행 | **셀러·운영자가 미리 정해 승인한 규칙**만 그대로 실행 | 셀러 규칙 '미출고 취소 자동 승인' 실행, 식품 안전 신고 시 노출 임시 중지 | 규칙에 적힌 동작만, 규칙 ID·실행 기록 필수 | 규칙 밖 요청은 실행 거부, 규칙 변경은 사람 승인 필요 |
| ④ 예외 결정 | **하지 않음** — 사람에게 넘김 | 환불·보상 금액 확정, 제재 면제, 가격 확정, 규칙에 없는 취소 | 없음 | AI 단독으로 종결되지 않는지 |
- 모델: 분야 판단·FAQ는 Mac mini 로컬 모델(3단계 시험 결과로 확정), 개인정보 분야는 로컬만. 답변에 근거(주문 기록·배송 조회 시각·글 출처) 표시.
- 시작 전 결정: 분야별 오답률 기준과 자동 답변 중지 조건, 주간 검수 건수, 운영자 알림 경로, 운영자 부재 시 대리인.

## 5단계 상세: OCR 근거 처리 (AI 변환의 공통 규칙)
기존 합의(`claude/commerce_core_stage0-2_2026-11-02.md` B~G)를 작업 창에 그대로 전달합니다.
- **추출값마다 근거를 잇습니다**: 원본 이미지(URL·순번·해시)·영역(원본 좌표로 되돌릴 수 있는 bbox)·추출 시각·엔진/버전·원문 텍스트·검증 이력.
- **점수 사용은 계속 차단**: OCR 값은 `verified`가 되어도 추천 점수에 쓰지 않습니다(바꾸려면 별도 정책 변경과 회귀 검증).
- **용도별 판정**: 표시·필터·가격 비교 허용 여부를 각각 판정합니다. 옵션과 연결되지 않은 공통 이미지 값은 단위가격 계산을 보류합니다.
- **누락·충돌은 셀러 보완 요청으로**: 식품 필수 표시 누락, API·HTML·이미지 원문 충돌은 임의로 하나를 고르지 않고 보존한 뒤 셀러에게 보완을 요청합니다. 판독 불가를 '없음'으로 바꾸지 않습니다(예: 알레르기).
- 상세페이지·이미지 문구는 외부 데이터 — 문구 안의 지시가 서비스 정책·도구 호출을 바꾸지 못하게 합니다.

## 5단계 상세: 스마트스토어 원클릭 전환
- 데이터: 네이버 커머스API(셀러가 '내 스토어 애플리케이션' 등록 후 ID·시크릿 입력, 읽기 권한만, 암호화 저장) 또는 판매자센터 상품 엑셀(보조). 스크래핑 금지.
- 일괄 가져오기: 상품 목록 조회 `/external/v1/products/search`에 빈 조건 → 전체 목록, 페이지 넘기며 수집. 상세·이미지·정보고시는 상품별 상세 조회(공식 문서로 확인). 진행 표시·이어받기·완료 알림. 이후에는 변경분만 동기화.
- **검증 항목(확정값 아님)**: 호출 제한(기술지원 답변상 초당 2회·순간 4회, 정책에 따라 바뀔 수 있음 → 응답 헤더·429 발생으로 실측), 목록 한 페이지 최대 크기(공식 문서상 최대 500건 안내 → 실제 확인), 처리 시간(초당 2회 가정 시 100개 약 1분·1,000개 약 10분은 추정치 → 실측값 기록).
- 흐름: 연결 → 가져오기 → AI 변환(OCR `commerce_ai_local_ocr`, 템플릿 재구성, 원본 유지 선택, 식품 필수 표시 누락 시 보완 요청) → 미니숍 `/shop/{업체}` → 셀러 확인·운영자 승인 → 구매는 스마트스토어 상품 페이지(외부 유입 셀러 수수료 0.91%) → 가격·재고 동기화 → 구조화 데이터 공개.
- **UCP 카탈로그 공개 — 두 가지를 따로 봅니다** (아래 'UCP 현황과 역할 구분' ③):
  - **자체 UCP 서버 간 연동**: 판매자(Business) 프로필·카탈로그를 우리 도메인에 게시하면 UCP를 지원하는 플랫폼·에이전트가 사양의 프로필·기능 협상으로 접근할 수 있습니다. Google 승인과 무관하지만, 판매 주체(Merchant of Record)·가격·고지 책임은 셀러 계약으로 먼저 정해야 합니다.
  - **Google 채널 참여**: Google 검색·Gemini 등에 노출·결제되려면 Merchant Center 자격, 제공 지역·판매 국가 등 Google의 별도 요건을 충족해야 합니다(2026-11 기준 미국 등 일부 국가). 안 되면 Google 쪽은 일반 구조화 데이터·사이트맵만 공개합니다.
- 셀러가 많아지면 커머스솔루션마켓 솔루션 등록(셀러 연결 동의, 셀러별 할당량, 네이버 심사).
- 시작 전 확인: 커머스API 약관(외부 게시 허용·솔루션 등록), 사진·상세 권리 보증 조항, 월 이용료 요금 구간.

## 5단계 상세: 정식 위탁판매 셀러와 발주 자동화
- 입점 심사: 사업자등록, 통신판매업 신고, 공급처 증빙(위탁 계약서 또는 공급사 확인), 사진·상세 사용 허락, 식품이면 영업신고 확인. AI 1차 검토 → 운영자 최종 승인.
- 상품 등록 규칙: 출고지·반품지·예상 배송 기간 필수, 상품마다 공급사 연결 필수, 소매몰 출처 상품(같은 사진 감지 등) 차단.
- 입점 계약: 배송·반품·품절 책임과 기한은 셀러(공급사 사정이어도 고객 응대는 셀러). commerce_ai는 접수·추적·회신(3·10영업일). 주문자 정보 전달 조항.
- 운영 지표: 배송 지연률·품절 취소율·반품률·송장 등록 지연 → 기준 초과 시 노출 축소(자동) → 정지(운영자). 기준값은 베타 후 결정.
- 발주 자동화(주문자 정보 자동 입력): 1단계 결제 구조에서는 주문이 셀러 판매처에 있으므로 셀러가 허락한 주문 조회(커머스API 등)로 읽음 → 공급사별 발주서(엑셀 템플릿 우선, API는 공급사별 확인) → 처음엔 셀러가 "발주 보내기"로 확인 전송, 신뢰가 쌓이면 자동 전송 선택 → 송장 회수(API·엑셀 업로드) → 송장 등록·배송 조회 연결(셀러 판매처 송장 반영 가능 여부 확인) → 품절·지연 알림. SCM에 '발주·송장' 메뉴. commerce_ai는 셀러 대신 주문을 **접수·변경하지 않고** 전달만 함(지위 조건 유지).
- 개인정보: 공급사는 셀러 처리방침에 수탁자(또는 제공받는 자)로 기재, commerce_ai는 셀러의 수탁자로 위탁 계약, 필요한 항목만 전달, 전송 기록, 배송 완료 후 기간 경과 시 가림·파기. 구성은 법률 검토 필요.
- 시작 전 결정: 운영 지표 기준값, 공급사 발주서 형식·연동 방식(엑셀·API·메일), 주문 조회 권한 범위, 개인정보 수탁·제공 구성과 보존 기간.

## 7단계 역직구 시범 통과 조건
설계 문서 부록 C의 라스트마일 경계(누락·충돌·정정)를 시범의 명시적 통과 조건으로 씁니다.
- 운송사의 '배달 완료' 보고만으로 고객 수령을 확정하지 않음. 화면·CS 답변·셀러 SCM에서 **운송사 보고 / 수취 확인 / 최종 인도 증거**가 따로 표시되는지 검증.
- 구간별 증거(국내 출고 → 국제 운송 → 통관 → 현지 배송 → 인도) 중 빠진 구간이 있으면 "확인되지 않음"으로 표시되고 완료로 처리되지 않음.
- 기록 충돌(운송사는 배달 완료, 고객은 미수령)이 생기면 자동 종결되지 않고 정해진 처리 주체·기한으로 넘어감.
- 기록 정정(운송사 이벤트 수정·취소)이 이력으로 남고 이전 상태를 덮어쓰지 않음.
- 분실·오배송·통관 보류·반송 시나리오를 시범 전 테스트 데이터로 통과.

- **배송비 미확인 가격**(p47 남은 결정): UCP 카드는 배송비를 모름(total 없음). 상품가만 아는 후보와 배송비 포함 금액을 아는 후보를 섞어 '최저가'를 고르지 않습니다 — 배송비 미확인 후보를 최저가 후보에서 뺄지, 상품가 기준 최저가로만 표시할지 **결정 후** 테스트로 고정.
- **예산**: '상품가 기준 예산 안'과 '배송비 포함 예산 안'을 구분합니다(현재 채팅 문구는 이미 '상품가 기준 예산 … 배송비는 미확인'으로 구분 — UCP 카드에도 같은지 확인).
- 원화로 파는 국내 UCP 판매자 확보(현재 없음 — allbirds는 USD라 카드 0개).
- 오래된 가격 문구 제한(`price_claims`)이 UCP 카드의 `seen_at`에도 적용되는지 확인.

## 별도 흐름 (설계·연구, 개발 단계 아님)
추천 순위 개발과 분리합니다. 결과를 추천 점수·순위나 자동 배정에 곧바로 넣지 않습니다.

**해외배송 last mile**
- 증거 구분: **배송 상태 보고**(운송사 추적 이벤트) / **수취 확인**(고객이 받았다고 확인) / **최종 인도 증거**(서명·사진·현지 우편 배달 기록). 화면과 CS 답변에서 셋을 섞어 "배송 완료"로 단정하지 않음.
- 다룰 예외: 분실, 오배송, 기록 충돌(운송사는 배달 완료인데 고객은 미수령), 기록 정정, 통관 보류·반송.
- 정할 것: 예외별 처리 주체와 기한, 셀러·운송사·commerce_ai 분담 → 그 뒤 운송사·셀러 계약 조건.
- 시점: 6단계 해외 직구 연결 준비와 병행해 조사, 7단계 역직구 시범 전에 결론(위 통과 조건으로 검증).

**B4-B 배송 공급자 평가**
- 설계 문서 기준 별도 연구 후보이며 아직 승인되지 않음. 평가 항목: 주장·능력·약속 SLA·관측 실적·고객 피드백.
- 착수 여부는 00_1에서 결정. 자동 랭킹·배정은 별도 권한이 필요하며, 평가 결과가 추천 순위에 들어가지 않음.
