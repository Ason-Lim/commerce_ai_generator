# 식품 상담 AI 비교 — DeepSeek · GPT · Claude (2026-11-11)

채팅의 식품 상담(제철·품종·손질·보관·먹는 법)에 어떤 모델을 쓸지 정하기 위한 비교.
결과 화면(아티팩트): "식품 상담 AI 비교" — 질문별 세 답 나란히, 블라인드 보기, 답 고르기 집계.

## 스크립트
`scripts/llm_food_compare.py`

- 서비스와 같은 조건: 시스템 프롬프트 `app/services/chat/food_tips.PROMPT`, 결과는 `food_tips.validated` 로 같은 검증
  → 화면에 실제로 나갈 답만 비교한다 (금지 내용·형식 오류는 서비스처럼 버려짐).
- 질문 20개: 품종·제철 12 · 손질·보관·먹는 법 8 (`QUESTIONS` 목록 — 바꾸거나 늘려서 다시 돌릴 수 있다).
- 기록: 답(원문·검증 후), 응답 시간, 입력·출력 토큰. 품종 이름은 국립종자원 목록(`data/reference/seed_varieties.json`)이 있으면 대조.
- 키는 `.env` 에서 읽고 결과 파일에는 남기지 않는다.

```
uv run python scripts/llm_food_compare.py                         # .env 의 모델 3개
uv run python scripts/llm_food_compare.py --gpt-model gpt-4.1     # GPT 모델 바꾸기 (--deepseek-model, --claude-model 도 있음)
uv run python scripts/llm_food_compare.py --only deepseek,claude  # 일부 모델만
```
결과: `var/llm_compare/food_compare_<시각>.json`. 60번 호출(20 × 3)에 몇 분·수백 원 수준.

주의: 최신 Claude 모델(claude-sonnet-5-5)은 `temperature` 를 받지 않는다(400 오류) — 스크립트는 빼고 호출한다.
관리자 LLM 연결(`app/admin/shared/llm.py`)도 anthropic 호출에서 temperature 를 뺐다 (2026-11-11).

> **이 비교의 쓰임 (2026-11-11 GPT 검토 반영)**: 모델 선택 참고용이다. 정답표가 출처로 확인된 것이 아니므로
> 순위·품질 점수·추천 근거로 쓰지 않는다. 식품 상담 평가는 출처 확인 정답표를 만든 뒤 다시 한다.
> 로드맵의 다음 단계는 그대로 '내부 근거 화면 + 회귀 확인'이다.

### 교차 확인 (app/services/ai/cross_check.py)
- 켜기: `.env` 에 ANTHROPIC_API_KEY 가 있고 `AI_CROSS_CHECK` 가 0 이 아니면. 모델 `CROSS_CHECK_MODEL` (없으면 ANTHROPIC_MODEL).
- 작업별 규칙 (2026-11-11 GPT 검토 반영)
  - 일반 팁(제철·품종·손질·보관·먹는 법): 검토가 실패해도 답은 나가되 "아직 다른 AI 의 검토 전이에요" 표시.
    이때는 저장하지 않는다(검토된 답만 저장) — 검토 기능이 꺼져 있을 때만 검토 없이 저장.
  - 안전 질문(`food_knowledge.SAFETY_RE`: 해동·생식·날로·덜 익힘·알레르기·영유아·이유식·임산부·수유·상함·변질·유통/소비기한·식중독·곰팡이·"먹어도 돼"):
    검토를 못 했으면 AI 답을 내보내지 않고 "판매처·전문가 확인" 안내만, 검토에서 의견이 갈린 줄은 단정 대신 보류 문구로 바꾼다.
    검토 안 된 안전 답은 저장하지 않는다.
- 검토 없이 저장된(예전) 답은 다음에 검토해 채운다.
- 화면: 검토 의견이 있는 줄 끝에 "_(검토 AI 의견: …)_", 안내 줄에 "DeepSeek 가 정리하고 Claude 가 한 번 더 검토했어요", 저장해 둔 답이면 정리한 날짜.
- 실측(2026-11-11, 딸기 제철·품종): 처음 14.5초(작성+검토), 같은 질문을 다른 말로 → 저장본 0.02초.
- 주의: 검토 프롬프트가 "확실하지 않으면 통과"라 너그럽다 — 위 비교에서 세 모델 모두 틀린 '금실 = 부드러움'을 이번 검토는 통과시켰다.
  검토는 '틀린 것을 줄이는 장치'이지 '맞다는 보증'이 아니다. 'AI 정리 · 확인된 사실 아님' 표시는 그대로 둔다.

### 확인된 사실 (app/services/ai/facts.py · verified_facts.json) — 2026-11-11
- 같은 AI 도 실행마다 답이 다르고(DeepSeek 금실 '단단' → '연함'), 두 AI 가 같이 틀릴 수 있다(Claude 검토도 '연함' 통과).
  지시문 예시에 딸기 문장을 넣었을 때 Claude 가 그 예시를 베껴 의견으로 냈다 → 예시는 검토 대상과 무관하게. 맞는 것은 **출처**로 정한다.
- 출처로 확인한 사실은 `app/services/ai/verified_facts.json` (git) 에 줄 단위로:
  식품·대상(품종)·항목·내용(statement)·**원문 문장(source_quote)**·원문 위치(source_ref, 예 Table 3)·적용 범위(applies_to)·
  **측정 조건(conditions)**·출처(기관·링크)·확인 방법·**확인자(reviewed_by)**·확인일·**상태(status)**.
  - statement 는 원문이 직접 말하는 범위만 적는다 (해석을 더하지 않음). '출처 확인' 표시는 원문 문장이 있을 때만.
  - status=active 이고 원문 문장이 있는 사실만 답에 쓴다. 출처가 바뀌었거나 다른 출처와 어긋나면 `needs_review` → 그동안 쓰이지 않음.
  - intrinsic (품종 고유 특성·기본 정보): 기한 없음. 사람이 고칠 때만 바뀐다.
  - seasonal (제철·출하 시기·시장 정보): review_after 까지만 쓰고, 지나면 재확인 대상.
- 답을 만들 때 확인된 사실이 AI 답보다 우선 → 그 줄은 "_(출처 확인 · 기관)_", Claude 의견은 붙이지 않음. 품종별 상품 안내에도 같은 내용.
- 첫 사실(2026-11-11, 원문 대조 — 사용자 확인 전):
  - 금실: 당도 높음·경도 우수·기존 수출 품종의 저장성 한계 개선 — 경남일보 2025-11-30 (경남도농업기술원 육성 품종 수상 기사)
