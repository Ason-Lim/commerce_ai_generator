## 추천 사유 · 예산 질문 · 관심 상품 (2026-11-01 p22) ✅ 실제 서버 확인

GPT는 이 기능의 **검증** 역할. 기준 테스트: `tests/services/chat/test_shopping_reasons.py` (12개)

### 왜 추천했는가
- 검색 순서 그대로가 아니라 후보 전체를 같은 기준으로 견준 뒤 **역할별로 최대 4개**: 가성비(100g당·개당 최저, 비교 가능한 후보 2개 이상일 때만, 아니면 '최저가') / 빠른 배송(쿠팡 로켓배송 표시 중 최저) / 넉넉한 양(가성비 상품보다 1.3배 이상 큰 것) / 선물용(고객이 선물을 찾을 때만, 상품명 표기) / 다른 선택. 나머지는 '다른 후보 n개'로 접어 둠
- 카드마다 **"왜 추천했나요"** — 사유 줄마다 근거 종류 표시: **비교 계산**(후보끼리 계산) · **판매처 표시**(로켓/무료배송) · **말씀하신 조건**(예산)
- 근거 없는 일반 문구("AI가 가격, 품질, 혜택을 종합해…")는 사유에서 제외
- 상품명의 1++·고당도·국내산·선물세트 등은 **'판매자 표기 (확인 안 됨)'** 로만, 사유·순서에 쓰지 않음
- 평점·후기·도착일: 쿠팡·네이버 검색 API가 제공하지 않음 → 만들지 않고 "판매처 페이지에서 확인" 안내. API가 주던 `isRocket`·`isFreeShipping`은 이제 보존(무료배송이면 총가격 확정)

### 예산은 말로
- 결과 뒤에 "예산이 있으면 말씀해 주세요(3만원 이하·5만원 정도·10만원대)" → 답하면 **재검색 없이** 찾은 후보 안에서 다시 고름, 예산 밖 후보는 '예산 밖' 표시, 없으면 그렇게 말함
- 첫 문장에 예산이 있으면("5만원 이하 한우 등심") 검색어에서 빼고 기준으로만 사용. '5만원 정도' = 10%까지 허용

### 관심 상품 · 최근 본 상품
- 카드 ♡ 관심 → 브라우저별 보관함(새 대화에도 유지). 서버는 그 세션에서 보여 준 후보에서만 복사(브라우저가 보낸 가격·URL 안 받음). 저장: 기존 `recipe_chat_session` 테이블의 `saved:<owner>` 행(새 DDL 없음)
- 헤더 '관심 상품'(대화 시작 후에만 보임) → 관심 상품 / 최근 본 상품(최근 검색 5번) 탭, **관심 상품 비교하기**(같은 검색에서 담은 것끼리만, 확인 시각 표시)
- 버그 수정: 다른 질문 후 이전 카드의 '결제하기'가 새 결과의 같은 순번 상품으로 가던 문제 → 카드 키 기반 `/go/{sid}/k/{key}`, 보관함은 `/go/s/{owner}/{key}`
- API: `GET/POST /api/chat/saved`
