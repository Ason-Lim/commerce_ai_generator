## 한 일
- **내부 화면 `/admin/evidence`** (관리자 로그인 필요, 관리자 탭 '근거'): 고객 화면과 같은 함수(`services.commerce.search.collect` → `explain.choose`)로 결과를 만들고 읽기만 함. 결과마다
  - 경로(주 경로 canonical / DB 예비 경로), 화면 순위·역할·선택 이유, 상위 엔진 순위·점수
  - 점수 구성: DB 경로는 trust_first → 클릭 → CTR·순위 대비 CTR → 가격 하락·CTR 피드백 → main.py 가산 단계별, 주 경로는 근거 구성요소 × 실제 가중치. **다시 계산한 값과 실제 값 일치 여부**
  - 점수에서 뺀 값과 사유(평점·리뷰·플랫폼, 결정일)
  - 가격 출처와 확인 시각: 실시간 / N일 전 / **오래된 가격(30일 초과)** / **확인 시각 없음**
  - 100g당 비교 가능 여부와 사유(옵션 목록·개수 불명확 등은 '비교 보류')
  - 평점 검증 표시 세 경우(없음·거짓·참) — 어느 경우도 점수 미사용, 고객 카드 배지로는 표시됨
  - **과거 행동 가점 적용 · 실제 노출 미검증** 표기
  - 문구 검사: 비교 불가인데 100g당·가성비 문구 / 확인 시각 없는·오래된 가격인데 가격 우위 문구
  - 경로 선택: 기본 DB 예비 경로(외부 호출 없음), '고객과 같은 경로'는 쿠팡 API 실시간 호출(확인 창)
- 코드: `app/admin/ops/evidence.py`(신규), `app/admin/web/evidence.html`(신규), `app/admin/routes.py`(경로 2개), 관리자 탭 링크
- `app/main.py`: DB 예비 경로를 `db_fallback_recommendations()`로 떼어 냄(내용 동일), 근거용 열 추가(`view_*` 점수 단계, `db_price_collected_at`) — 고객 카드가 읽는 `seen_at`은 만들지 않음
- `app/services/recommendation_pipeline.py`: 주 경로 결과에 `canonical_score`(구성요소·실제 가중치·설정 가중치·버전) 추가 — 고객 카드는 읽지 않는 키

## 발견 (1단계 범위 밖 — 기록만)
1. **고객 화면이 오래된 가격으로 가격 우위 문구를 냄**: DB 경로 실데이터에서 '가성비'·'가장 낮아요' 문구 20건이 130~198일 전 가격에 붙음 (`stage1_display_d1.md`). 주 경로(쿠팡 실시간)에서는 해당 없음
2. **노출·클릭 기록**: 모든 행동 기록이 2026-07-16 이후 없음. CTR 분모 `recommendation_impression_log`는 2026-05-30이 마지막이고 앱 코드에 쓰는 곳이 없음. 클릭 582건 전부 Streamlit, **채팅 클릭 0건** — 채팅의 /go·/api/click 기록이 실제로 쌓이는지 확인 필요(실패해도 경고 로그만). 기존 `EXPOSURE_UNVERIFIED` 유지
3. **행동 가점이 DB 경로 순위를 좌우**: 행동 가점 6종(click·ctr·rank_ctr·ctr_feedback·product·mode)을 뺀 순위와 비교하면 45개 조합 중 33개가 바뀌고 25개는 상위 10 구성이 바뀜 (`stage1_behavior_counterfactual_2026-11-10.md`, 재현 검사 일치). 가점을 빼면 남는 순서는 대부분 동점 고정 순서라 '더 나은 순위'라는 뜻은 아님 — DB 경로에서 상품을 구분하는 것이 과거 행동 기록뿐이라는 뜻
4. **관련성**: '망고' 질의에 '샤인머스켓 망고포도'가 가성비 1위 — 상품명에 '망고'가 들어간 다른 품목
5. 주 경로 호환 응답의 `score`는 canonical 최종 점수가 아니라 `v7_final_score`에서 옴(enrich_response_compatibility) — 화면 근거에서는 `canonical_score`로 따로 표시
