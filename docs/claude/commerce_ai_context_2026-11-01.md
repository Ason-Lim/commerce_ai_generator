## 1. 구성

- **commerce_ai_generator** (FastAPI, :8001): 대화 API, 레시피, 트렌드, 관리자(`/admin`)
- **integrated_system/ui_ux** (React + Vite 6, :5173): 고객 화면. `/api`, `/go` 만 백엔드로 프록시
- 데이터 폴더(맥북): 네이버 식품 검색어 순위 CSV(매일, `date,rank,keyword`), 구글 트렌드 CSV(매일 상승 검색어 ~20개)
- LLM: **DeepSeek 하나**(대화 해석·쉽게 보기·AI 제안 레시피·트렌드 원인 추정). 키는 서버 `.env`에만, React에 노출 금지
- 이미지: OpenAI Images. dall-e-3 종료 → `gpt-image-1` 승인 대기 중 ⏳
- 판매처: 쿠팡 파트너스(상품), 네이버 쇼핑커넥트(블로그 수익화, 링크 수동 등록)

## 2. 반드시 지키는 원칙 (사용자 지시)

1. 원본 폴더 보존. **커밋·푸시·배포는 하지 않음** (변경 전 파일은 `recipe_chat_api_backups/<날짜>_pN/` 에 백업)
2. 외부 폴더 동적 로딩·`sys.path` 추가 금지, `/Users/...` 경로를 운영 코드에 넣지 않음 (경로는 `.env` 로만)
3. React 인트로의 디자인·문구·레이아웃·예시 카드·입력창은 바꾸지 않음 (예외: 글씨 1~2단계 키움, 헤더에 트렌드 탭 아이콘 추가)
4. 테스트 통과를 위해 기대값을 임의로 바꾸지 않음
5. 검증용 검색어·내부 주소·호출 기록은 **개발 모드(`CHAT_DEV_TRACE=1`)에서만**, 고객 응답에는 넣지 않음. 검증 후 끔
6. 블로그·외부 글은 **제목·날짜·링크만** 사용. 본문·사진·영상 복사 금지
7. AI 제안은 "특정 블로거·유명인 레시피 재현"으로 표현하지 않고, 원문에서 가져온 것처럼 보이게 하지 않음
8. 확인되지 않은 것은 확정하지 않음 (예: 네이버 API 키 만료일, "출처 n곳 = 독립 출처" 같은 표현)
9. 설명은 한국어

## 3. 레시피 기능 — 단계별 정리

### 1단계 · 레시피 카드 + 공공 카탈로그
- 카탈로그 5,198건 → `recipe_catalog` 테이블. 출처: 식품안전나라(COOKRCP01), EPIS. **농사로 향토·종가음식은 사용 안 함**
- 사진은 이용 조건을 확인한 출처만 표시

### 2단계 · 쉽게 보기
- DeepSeek가 원문 단계를 정리 → 서버가 원문과 대조(모든 단계 포함, 새 숫자·재료·분량 금지), 실패 시 1회 재시도 후 원문
- 백그라운드 생성 + 캐시(`recipe_easy_view`)

### 3단계 · 완성 사진 먼저 · 부족한 재료
- 카드 순서: 완성 사진 → 설명 → 재료 → 부족한 재료 → 만드는 순서 → 팁
- EPIS는 AI 생성 이미지("AI 생성 예시 이미지" 표시, 하루 상한)
- 부족한 재료: 고객이 '부족/없음' 표시 → **'부족한 재료 상품 보기'를 누를 때만** 상품 검색

### 4단계 · 품질·출처
- 카드 가능 4,494건(86.5%). 출처는 카드 맨 아래. AI 기본법(2026-01-22) 표시 의무 → AI 다듬음·AI 이미지 표시 유지

### 5단계 · 관리자 통합 (`/admin`)
- 운영 탭(판매처 API 점검, 대화·추천 기록, 결제 뼈대) / B2B 탭(공고 분석·입찰 모니터·공급사 근거). 토큰 1개로 로그인

### 6단계 · 실행 가능한 조리 설명 (easy-v3)
- 단계별 "다음으로 넘어가는 때", 필요한 단계만 주의점. 원문 구절은 '원문', 아닌 것은 '일반 제안'으로 구분
- 기본 재료표에서 컵→mL 자동 환산 제거(원문이 컵 용량을 정하지 않음)

### 7단계 이후 (10/29~10/31)
- **검색 후보가 고객의 핵심 조건을 지킴**: 예) "갈비구이 만드는 법" → 먼저 LA갈비·돼지갈비·양갈비 중 무엇인지 물음. 정확히 같은 이름을 맨 앞에. '구이·말이·볶이' 같은 끝말은 잘리지 않게 보호
- **보유량은 고객 표현 그대로 저장**: "모시조개 1컵", "숟가락 2개"처럼 저장하고 정정·재접속 복구 지원. g·mL 재입력을 강요하지 않음(고객 편의)
- 재료표: 고기 먼저, 생선·해산물 따로
- **원문 보충**: 원문이 부실하면 "일반 조리 제안(원문 아님)"으로 보충하고 출처·참조 표시
- 글씨 크기 1~2단계 키움(안내문 15px 등)

## 4. 신규 요리·트렌드 검색 (discover)

고객이 공공 카탈로그에 없는 요리를 물을 때(예: **두쫀쿠**)의 흐름.

1. 요청을 **트렌드 / 새 요리 / 링크** 로 구분
2. 네이버 검색 API(블로그·뉴스)로 후보 찾기 — 검색어에 항상 "레시피" 추가, 제품·키트·후기 글 제외, 외부 후보 최대 3개
3. 후보는 **'제목 기준 레시피 후보'** 로 표시. 비슷한 요리는 '관련 레시피'로 분리(같은 원본처럼 연결하지 않음)
4. 트렌드 질문: 기사에서 유행을 언급한 근거 ≠ 관심 상승 검증. '관련 기사 n건'으로만 표시, '확인이 필요한 이름'은 따로
5. 후보 카드 버튼: **원문 보기(새 창으로 열림, 메인 화면 유지)** / **AI 제안 레시피로 만들기** / 후보 비교
6. **AI 제안 레시피**(`ai_recipe.py`)
   - 입력은 요리 이름뿐(외부 글 본문은 읽지도 옮기지도 않음)
   - 모를 때는 먼저 한 가지 질문("어떤 재료로 만드는 디저트인가요?")
   - 검증: 재료 3~14개(숫자+단위), 단계 3~8개, 사람·채널·상호 표현 금지
   - 카드에 "AI 제안 레시피 · 원문 아님", 생성 시각·모델·재료/단계 수 표시. 별도 저장(`ai-<해시>`)
   - 이후 기존 흐름 그대로: 재료표 → 인분 변경 → 보유량 기록 → 부족 재료 → 상품

**실제 검증 완료 ✅ (11/01)**: 두쫀쿠 검색 → AI 제안 → 재료표 → 20개 분량 변경 → 보유량 50g → 30g 정정 → 부족·없음 표시 → 요청 후 상품 → 새로고침 후 복구까지 실제 서버로 확인. 검증 중 실패 4건(분량 변경이 상품 검색으로 감, 괄호 재료명 미인식, "50g 말고 30g" 정정 실패, 머리글 중복)을 고쳐 반영. AI 제안은 **형식 검증만** 통과(맛·조리 성공 미검증). `CHAT_DEV_TRACE=0` 적용·확인. 관련 공공 레시피는 고객이 고른 뒤에만 전환됨. 시나리오 3(같은 이름 공공 레시피 자동 연결)은 여전히 **미검증**.
새로 발견: 공공 레시피 후보가 요리 종류를 지키지 않음(들기름 막국수 → 배추만두 등), 보유량 질문에 기록값 대신 필요량을 답함, 부족 재료 상품에 업소용 대용량 섞임.

## 5. 쇼핑 검색 정확도
- 문제: "휘태커스 초콜릿 중에 할로윈에 좋은 것" 같은 문장 전체가 쿠팡 검색어로 들어가 엉뚱한 상품이 나옴
- 해결: 짧은 문장은 그대로 / "X 중에" → X / 그 외에는 DeepSeek로 핵심 상품어 추출(검증 후 사용) → 결과 제목과 검색어 관련성 검사(바이그램 0.5 이상)
- 못 찾으면 "쿠팡에서 **X** 관련 상품을 찾지 못했어요" + (등록된 경우) 네이버 쇼핑커넥트 링크 안내. 링크는 사용자가 직접 발급·등록

## 6. 휘태커스 조사 → 급상승 모델의 출발점
- 뉴스: 2026년 10월 기사 1건(뉴질랜드 한정판), "휘태커스 할로윈" 기사 0건 → 언론 마케팅 흔적 약함
- 데이터랩: 9월 평균 지수 6.8 → **10/13 100**(급등) 후 40~80 유지. 할로윈은 10/30 정점, 휘태커스는 10/23 이후 하락. 2025년 같은 시기는 평탄
- 결론: 방송·기사보다 SNS 확산 가능성. 기존 식품 순위의 '급상승' 표시는 결측일을 501위로 계산하는 등 결함 있음 ⏳(수정안 제안됨, 결정 대기)

## 7. 급상승 트렌드 모델 (2026-10-31 신규)

### 흐름
**① 데이터랩 급상승 → ② 블로그 탐지 → ③ 구글 트렌드 → ④ 교차 확인 · 리포트**

- **감시 대상**: 식품 검색어 순위 상위 500 + 고객이 채팅에서 찾은 검색어
- **① 데이터랩**: 60일 일별 지수, 5개씩 묶어 요청(상대값이라 **자기 평소 대비 배수만** 비교)
  - 평소 = 35~8일 전 중앙값, 최근 = 최근 3일 평균, 최고 = 최근 7일 최고
  - **급상승**: 최근/평소 ≥ 2.0배 그리고 최고/평소 ≥ 3.0배. 그 밖에 '새로 등장', '반짝 후 하락', '상승'
  - 후보 상위 40개는 단독으로 다시 요청해 정밀 확인. 네트워크 오류는 2회 재시도(한도 초과는 재시도 안 함)
- **② 블로그**: 최신순 100건의 **제목·날짜만**. 상승 시작일 전후 글 수 비교, 제목 단서 분류 — 방송 / SNS·유튜브 / 쿠팡 / 편의점 / 할인·행사 / 출시·한정 / 선물·시즌
- **③ 구글 트렌드**: 매일 수집한 상승 검색어 CSV에 나왔는지
- **④ 교차 확인**: 블로그 글 증가 · 식품 순위 상승 · 구글 — n/3
- **계기 추정**: DeepSeek가 블로그 제목만 보고 추정, "AI 추정 · 블로그 제목 기준" 표시. **가격·건강 효능·질병·식중독·사고 같은 확인되지 않은 주장이 들어가면 고객 화면·블로그 초안에서 제외**(관리자에만 표시)
- 한계: 데이터랩은 하루 단위·전날까지(실시간 아님), 사람/매크로 판별 불가, 오래 이어진 상승은 '평소'에 상승분이 섞여 배수가 작게 나옴

### 화면
- **고객 '지금 뜨는 식품' 탭** (`/#/trends`, 헤더 아이콘): 배수·시작일·30일 그래프·단서·추정 계기, **"추천 상품 보기"** → 대화로 돌아가 그 상품을 물어봄
- **관리자 트렌드 탭** (`/admin/trends`): 요약 KPI, 급상승 목록, 60일 그래프(평소 구간·시작일 표시), 시작일 전후 블로그 제목, 순위 변화, 구글, **applesodda 블로그 초안**(수수료 고지·쇼핑커넥트 삽입 자리·가격 없음, 텍스트 파일로만 저장)
- 토큰 없이 보는 **둘러보기 모드**(`.env` `ADMIN_GUEST_TRENDS=1`): 트렌드 리포트 읽기만 가능. 실행·초안·운영/B2B 탭은 토큰 필요

## 8. 운영·테스트 환경
- 백엔드 실행: `API_RELOAD=1 ./run_api.sh` (코드 변경 자동 반영)
- 외부 테스트: `cloudflared tunnel --url http://localhost:5173 --http-host-header localhost:5173`(고객), `cloudflared tunnel --url http://localhost:8001`(트렌드 리포트) — 무료, 주소는 실행마다 바뀜, 맥북이 꺼지면 끊김. 고정 주소는 도메인 비용(.com 연 약 10달러)만 들고 터널은 무료
- 테스트: 전체 약 4,930개 통과, 기존부터 있던 실패 6개(이번 작업과 무관)

### GPT와 논의하면 좋을 질문 예시
- 급상승 판단 기준(2.0배/3.0배, 평소 구간 35~8일)이 적절한가? 오래 이어지는 상승을 어떻게 다룰까?
