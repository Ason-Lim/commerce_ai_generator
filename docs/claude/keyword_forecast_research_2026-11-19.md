## 0. 무엇을 예측하나 (문제 정의)

예측 대상은 "검색량"이 아니라 우리가 가진 **식품 분야 하루 상위 500 순위**다. 질문은 세 가지로 좁힌다.

| 질문 | 출력 | 쓰는 곳 |
|---|---|---|
| Q1. **예측일 현재 100위 밖인 관측 키워드 중, 7·14·28일 안에 한 번이라도 100위 안에 진입할 키워드는?** (GPT 1차 — 상위권 '유지'는 별도) | 키워드 · 예상 진입 주 · 예상 최고 순위 **구간** · 근거(어느 동인) · 등급(반복/후보) | 발급 링크·블로그를 **미리** 준비 (상업적 핵심) |
| Q2. **지금 오르는 키워드가 언제 꺾이나?** | 예상 정점 **주간(구간)** · 정점 뒤 하락 속도 | 글 게시 시점·링크 달기 마감 |
| Q3. **돌발 수요가 생겼나?** (예측이 아니라 **조기 감지**) | 당일 경보 + 미리 짜 둔 상품 묶음 | 비상식량·생수·구급·영양제 글 즉시 발행 |

### 왜 "미리"가 중요한가 — 작년 데이터로 확인한 선행 기간 (2026-11-19 밤 확인)
| 행사 | 키워드 | 행사 3주 전 | 2주 전 | 1주 전 | 당일 | 이틀 뒤 |
|---|---|---|---|---|---|---|
| 빼빼로데이 2025-11-11 | 빼빼로 | 20위 (10-20) | 2위 (10-28) | **1위** (11-04) | 1위 | 26위 (11-13) |
| | 빼빼로만들기 | 96위 | 29위 | **10위** | 56위 | 100위 밖 |
| 수능 2025-11-13 | 수능선물 | 33위 | 8위 | **2위** (11-04) | 14위 (11-11) | 100위 밖 |
| 초복 2025-07-20 | 삼계탕 | 95위 (07-05) | **26위** (07-13) | 34위 | 44위 (당일) | 100위 (07-25) |

→ (GPT 검토 뒤 고침, §7-2) 표의 칸 이름과 실제 날짜가 어긋나 **일반화 근거로는 부족**하다. 말할 수 있는 것: 일부 행사 키워드는 행사 **전에** 상위권에 진입하고, 준비형('만들기')은 완제품과 다른 시기에 오를 수 있다. 정확한 정점·하락 시점은 **선행 곡선 탐색기**(일별 전체 곡선)로 검증한다. 링크·글을 행사 전에 준비해야 한다는 목적은 그대로 — 이것이 모델의 존재 이유다.

## 3. 모델 (단순한 것부터, 층층이)

### B-0. 기준선 3종 (GPT 1차 §3 — 순위는 검색량이 아니므로 비율 보정 없음)
- ① **최근 상태 유지**: 최근 7일의 100위 안 여부·순위를 그대로 (전년 자료가 없는 키워드의 바닥) ② **전년 계절 반복**: 작년 같은 주(d+h−364±3일)의 관측 결과 ③ **행사 상대일 반복**: 작년 같은 행사까지 남은 일수에 맞춘 관측 결과.
- 모든 모델은 이 셋과 **같은 조건**(같은 as_of, 같은 후보 집합)에서 비교. (예전 '올해/작년 순위 비율 × 보정' 식은 폐기.)

### B-1. 행사-상대일 모델 (A·B·C)
- 키워드마다 **행사 기준 상대일 −35…+14 의 순위 곡선**을 해마다 따로 보고(평균하지 않음 — 순위는 검색량이 아님), 진입 선행일·정점 구간은 해별 값의 중앙값. (빼빼로 2025: −22일 20위 → −7일 1위 → +2일 26위.)
- 올해 행사 날짜(달력)에 곡선을 얹어 예측. 음력 행사는 날짜가 달라도 곡선은 상대일이라 그대로 쓰임.
- 키워드↔행사 연결은 **데이터로 찾는다** (구현 `forecast/events.py`): 기준 구간(−35…−29) 대체로 100위 밖 → 진입 구간(−28…행사 끝) 100위 안 → 이탈 구간(행사 끝 +3…+14) 대체로 100위 밖. 구간별 최소 관측일(4·20·8)을 못 채운 해는 '자료 부족'으로 판정에서 뺌. **판정 가능한 해 2개 이상이 모두 만족 = '반복'(행사 전후 반복 패턴), 한 해만 = '후보'**. '결속'이라는 말은 인과처럼 읽혀 쓰지 않음(GPT 2차 ②). 사람이 만든 목록(선물세트·한과·떡국떡·송편·삼계탕·전복·초콜릿·사탕·카네이션…)은 씨앗으로만.
- 상태 셋: 순위(1~500) / 'out'(정상 파일에 없음 = **100위 밖으로 사용**) / None(파일 누락 = 판단 불가, 집계에서 뺌). 501 대입 없음 (GPT 2차 ①).
- 정점: '최고 순위의 25% 안' 대신 **최고 순위 연속 구간(peak_best)** 과 **20위 안 연속 구간(peak_top)** 둘을 냄 (GPT 2차 ④).
- 연속 행사군: 복날(초복~말복)·설/추석 연휴는 시작 행사 기준 상대일에 **끝 행사 뒤 +3…+14** 를 이탈 구간으로 — 초복 하나만 보면 삼계탕이 '지속형'으로 탈락하기 때문 (GPT 2차 ⑤).
- 출력: 예상 진입 주, 예상 최고 순위 구간(행사 −k…−j일), 다음 행사 날짜에 얹은 '예보 재료'.

### B-2. 계절 기준선 모델 (D·F)
- 연중 위치(주차)별 순위 곡선을 해마다 보고(행사 반복 패턴이 아닌 키워드). 올해 **첫 100위 진입이 작년보다 빠른지/늦은지**로 곡선을 당기거나 미룸(과메기·대방어가 올해 2주 빨랐으면 뒤 흐름도 당김).
- 김장처럼 날씨가 당기는 품목은 B-3 과 합성.

### B-3. 날씨 반응 모델 (E·F)
- 키워드별로 일 순위(또는 100위 안 여부)를 **당일·3일 평균 기온, 전일 대비 기온 하락폭(한파), 강수, 미세먼지**로 회귀(단순 선형 또는 로지스틱, 계절 항 포함). 두 해 자료면 **반응 계수가 뚜렷한 키워드만** 채택(나머지는 B-2).
- 예측은 **기상 예보 7~10일**을 넣어 산출. "이번 주말 첫 영하 → 호빵·어묵·군고구마 진입 확률 ↑, 절임배추 앞당김".

### B-4. 돌발 수요 — 예측 대신 '준비 + 조기 감지'
- **사전 묶음**(상품·글 틀을 평시에 준비): 비상식량(햇반·통조림·라면·생수2L·에너지바), 정전(건전지·랜턴·보조배터리는 식품 밖→제외), 구급(식품 분야 밖 — 제휴 가능 여부 확인), 감염병(비타민C·D·아연·프로폴리스·홍삼 — 건기식 표현 제약), 폭염(이온음료·생수·얼음), 폭설·한파(즉석국·누룽지).
- **트리거**: ① 기상특보·재난문자(API 또는 수동 버튼) ② 급상승 감지에서 '비상 묶음' 키워드가 하루에 2개 이상 동시 상승 ③ 순위 당일 급등(전일 대비 200계단↑)이 묶음 안에서 발생.
- 트리거가 켜지면 **그날 안에** 준비된 묶음 글을 점검·발행. 2024·2025 자료에서 과거 사건(태풍·폭염·지진 등 날짜 목록)을 찾아 묶음 키워드가 실제로 움직였는지 **사후 검증**부터 한다(움직이지 않는 키워드는 묶음에서 뺌).

### B-5. 합성과 신뢰 등급
- 키워드마다 적용 모델을 하나 고른다: 행사 반복 → B-1, 날씨 계수 뚜렷 → B-3(+B-2), 나머지 → B-2, 전년 자료 없음 → B-0 ①(최근 상태 유지).
- 등급은 당분간 **반복 / 후보** 만. '높음·보통' 같은 신뢰 등급은 과거 예측 성과·표본 수·자료 충실도가 쌓인 뒤에 (GPT 1차). 화면엔 등급과 근거(어느 동인·어느 해·판정 이유)를 함께.
- 기계학습(예: 그래디언트 부스팅)은 2027년 자료가 쌓인 뒤 검토. 지금은 **규칙+통계**가 설명 가능하고 2년 자료에 맞다.

## 4. 평가 (만들기 전에 기준부터) — GPT 1·2차 반영
- **자료 구분**: 2024·2025 = 탐색·개발 자료(규칙을 보고 만들었으므로). 2026 도 이미 보았으니 '완전 미사용'은 아님 — **최종 평가는 앞으로 매주 쌓이는 실제 예보 vs 실제**로 한다. 과거 구간 백테스트는 규칙 비교용.
- **정보 누출 통제**: 모든 예측에 **기준일 as_of** — 그날까지의 파일만 읽고(`load_window(as_of=…)`), 후보 키워드도 as_of 이전 자료로만 고르고, 이탈 구간이 as_of 전에 끝난 해만 판정에 쓴다. 과거 실측 날씨를 예보처럼 넣은 결과는 운영 성능으로 치지 않음.
- **지표**: ① Q1 — 기준일에 100위 밖이던 후보가 7·14·28일 안 100위 진입했는가(정밀도·재현율) ② **주간 상위 20 제안 적중률** ③ **최초 진입까지 확보한 선행 일수** ④ **놓친 주요 상승 키워드 비율** ⑤ **불필요한 준비 작업 수** ⑥ **기준선 3종 대비 추가 적중 건수** ⑦ 정점 **구간** 적중 여부.
- 전체 후보 성적과 **사전에 정한 행사·계절 후보** 성적을 둘 다 보고 — 실패를 사후에 '바이럴'로 분류해 빼지 않음.
- 행사별 리포트카드: 설·추석·복날·수능·빼빼로·발렌타인·어버이날·김장 각각 "몇 개를 몇 주 전에 맞혔나". 예측 적중과 방문·구매 성과는 **분리**해 기록.
- +15%p·±4일은 **잠정** — 기준선 성적·행사별 표본 수 확인 뒤 확정.

  2. 기업명·브랜드명이 제목 앞에 오고 동사가 "선보이다/출시하다" → +2 (품목·시장 기사면 0)
  3. 같은 제목이 여러 매체에 동일 문장으로 실림(보도자료 배포) → +1 (제목 유사도 ≥0.9 가 3건 이상)
  4. 매체 분류: 경제지 유통면 '기업 소식' 섹션 URL 패턴 → +1
  5. 반대로 가점(남김): "가격|물가|작황|출하량|수입|관세|리콜|회수|기후|폭염|한파|조사 결과|통계" → −2, 정부·기관 출처(aT·농식품부·기상청·식약처·통계청) → −2
  임계 ≥3 제외. 규칙은 `data/news_ad_rules.yaml` 로 빼서 운영에서 고침. 사람이 제외/복원하면 학습 표본으로 저장(나중에 분류기).
- **리포트 쓰임**: 키워드 카드의 '계기' 칸 — 기사 제목·매체·날짜 **링크만**(본문 인용 없음, 저작권). AI 요약은 "기사 n건은 ~를 다룸" 한 줄. 급상승 계기 추정(surge.ai_cause)의 근거에도 뉴스 유무를 넣음.
- **본문 출처**: 네이버 뉴스 API 는 제목·요약(description)·링크·날짜만 준다 → 1차 필터는 **제목+요약 기준**. 본문 수집은 하지 않음(저작권·부하). 필요하면 originallink 로 사람이 확인.
- **명시적 광고 표시와 일반 신호 분리** (GPT 2차): "[AD]·광고·협찬·제공·보도자료" 같은 **명시 표시는 가점으로 상쇄되지 않고 바로 제외**. 점수 규칙(위 1~5)은 명시 표시가 없는 기사에만.
- **중복 제거**: 제목 유사도 ≥0.9 기사는 **한 묶음(보도자료 배포)** 으로 세어 근거 1건으로 — 3건이 독립 근거 3개가 아님.
- **'관련 보도'와 '원인 가설' 구분**: 같은 시기에 기사가 있다는 사실은 '관련 보도 n건'으로만 표시. 급상승 원인으로 쓰는 것은 AI 추정('원인 가설')이라고 따로 표기.
- **블로그엔 넣지 않음** — 블로그는 상품·레시피 중심(연구 방향 2026-11-19). **별도 단계**로 개발(§6 8).
- 구현 위치: `app/services/trends/news.py`(수집·필터) → 리포트 생성기(§6 7단계)에서 호출. 테스트는 저장한 응답 샘플로.

### 9-2. 모델 `app/services/trends/forecast/prices.py` (B-6, 해마다 따로 · as_of · 첫 값)
- **현재 위치** `position`: 최근 관측가, 1개월·1년 전 대비(±3일 가장 가까운 관측), 52주 창 백분위(같은 값은 절반으로 세는 중간 순위)·최저·최고·관측일.
- **전망** `outlook`: 전년 같은 날짜 → +7·14·28일 비율을 **해마다 따로**(2024·2025) + 중앙값·범위·방향 일치 여부. 평균하지 않음.
- **행사 상대일 곡선** `relative_curve`: 김장 시즌·추석·복날 기준 −42…+28일, 기준 구간(−42…−29) 중앙값 = 1.0 비율. 행사 선행 곡선(B-1)과 같은 꼴.
- **매수 시점** `buy_timing` (첫 값): 보류(52주 관측<20 또는 전년 비교 해<2) / 기다리기(28일 전망 중앙값 ≤ −5%, 가장 낮은 지평을 '언제'로) / 지금(전망 ≥ +5% 이고 상위 30% 아님, 또는 하위 30% 이고 내림 전망 없음) / 분할(그 밖·해마다 방향 다름·비싼 구간). 이유 문장에 전망 범위·해 수·현재 자리.
- **동인** `active_drivers`: 품목의 동인 목록 + as_of 이전 최근 신호 상태. **수치에 넣지 않고 이유로만** — 지연 일수가 품목마다 달라 검증 전엔 가중치를 줄 수 없음.
- 백테스트: 가격도 B-0 기준선(최근 유지·전년 반복)과 같은 조건으로. 지표(첫 안): 28일 뒤 방향 적중률, '기다리기' 뒤 실제 최저가가 판정 시점보다 쌌는지(절약률), '지금' 뒤 4주 안 더 싼 날 비율.

### 9-4. 해외 직구 견적 `app/services/trends/forecast/overseas.py` (UCP·Shopify)
- UCP 카드 변환은 원화만 카드로 만든다(p40~p47). 여기서는 catalog.search 응답의 **외화 옵션**을 따로 읽어(`foreign_variants`) 견적만 낸다 — 추천 카드·순위·가성비 판정에 섞지 않음.
- `quote`: 현지가 × 환율(질의값 `fx_usd` 또는 `FX_USD_KRW` — 출처·날짜 함께; 자동 조회는 다음 단계) + 국제 배송 추정(500g 단가표, 자리 표시 값) + 면세 한도(자가사용 목록통관: **미국발 200달러, 그 밖 150달러**, 같이 담은 물품 합산) 초과 시 관세(품목표: 올리브유·커피·초콜릿·견과·파스타 8%, FTA 0% 는 원산지 증명 때 — **확인 필요**) + 부가세 10% → 도착 추정가 → 100g당. `estimate=True` 와 메모 항상.
- **검역 차단**: 축산(육류·계란)·축산가공(유제품)·수산·생과·국산·김장 품목군은 allowed=False — 견적 없음(소고기·양고기·계란·치즈는 '국내 비교만').
- **식품 구매대행 영업등록 확인 전엔 '참고 견적'** 꼬리표(sale_types 설계 2026-11-06 4단계와 같은 선). 주문·결제 없음. cross_border(landed_cost 근거 틀)와 연결은 다음 단계.
- `compare`: 국내 최저 100g당 vs 직구 최저 100g당 → 차이 %·어느 쪽이 싼지. 중량 모르는 상품은 비교에서 뺌.
