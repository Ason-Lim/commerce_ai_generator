# R3 — DB 예비 경로의 역할 결정안 (2026-11-10, 결정 대기)

## 지금까지 확인된 사실
| 항목 | 내용 | 근거 |
|---|---|---|
| 언제 쓰이나 | 주 경로(쿠팡 실시간)가 실패할 때만. 발생률은 아직 모름(경로 기록을 11-10에 시작, R0 통제 검증 진행 중) | `r0_path_click_report_2026-11-10.md` |
| 가격 | 표시 96건 **전부 과거 가격**(마지막 수집 07-16), 50건은 100g당 비교 불가 | `stage1_display_d4_relevance.md` |
| 점수 | 평점·리뷰·플랫폼·행동 신호를 뺀 뒤 상품을 구분하는 것은 고당도 표기 여부(2값)·가격 하락(과거)·문맥 가산뿐, 나머지는 동점 고정 순서 | `stage1_evidence_screen_2026-11-10.md` 후속 3 |
| 상품 범위 | 과일 7종 294건 (네이버 쇼핑 API 시절 수집) | `stage1_view_identity_price_check_2026-11-10.md` |
| 주 경로와 비교 | 주 경로도 순위는 사실상 **가격순**(가격 순위 상관 0.93~1.00, '가격만'과 1위 12/12 같음), 품질 점수는 상품명 표기에서 나온 값 | `r1_canonical_evidence_2026-11-10.md`, `r1_quality_contribution_2026-11-10.md` |

→ DB 예비 경로는 **가격 경쟁력을 판정할 근거가 없음**. 남는 가치는 "주 경로가 실패해도 요청 품목에 맞는 후보를 찾아 판매처로 안내"하는 것뿐일 수 있음.

## 선택지
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ① 현행 유지 | 지금 점수(고당도+가격 하락)로 정렬, 과거 가격 문구 제한 | 변경 없음 | 근거 없는 순서, 오래된 상품 목록 |
| ② **단순 관련성 정렬 + 판매처 안내** | 검색어 관련도(품목 일치·관련성 필터) → 확인일 최근 순으로만 정렬, 역할 배지·가격 비교 없이 "판매처에서 가격 확인" 안내 | 근거 있는 것만 말함, 단순·투명 | 가성비·최저가 선택 기능 없음(예비 경로에서만) |
| ③ canonical 점수기로 다시 계산 | DB 후보도 주 경로 점수 체계(가용 근거 재배분)로 | 점수 체계 하나 | DB 가격이 과거라 price 근거부터 문제 — 실질은 ②와 비슷하거나 더 나쁨 |
| ④ 예비 경로 폐지 | 주 경로 실패 시 "지금 상품을 불러오지 못했어요" + 네이버 쇼핑 검색 링크 | 오래된 데이터 노출 없음 | 실패 시 보여 줄 후보가 없음 |

## 제안
- **②를 우선 후보로, ④와 함께 비교**한다 (GPT 검토 의견과 같음). ③은 과거 가격 문제를 풀지 못해 제외.
- 판단 순서: R0로 **실제 발생률**을 먼저 본다 — 거의 안 쓰이면 ④가 단순하고, 자주 쓰이면 ②.

## 비교 방법 (R4)
- 고정 질의 세트: 지금 DB에 있는 과일 7종 + 문장형 질의(예산·선물) 약 15개
- 사람이 판정: 질의마다 "요청 품목에 맞는가 / 판매처로 안내할 만한가" (가격 판정은 하지 않음)
- 비교 대상: 현행 d4 vs ② 정렬. 지표 = 품목 불일치 수, 안내 가능한 후보 수, 문구 경고 0 유지
- 결정은 사용자. 결정 전에는 현행(①, 문구 제한 적용 상태) 유지

## 결정 필요
- R0 발생률을 본 뒤 ② / ④ 중 무엇을 비교 실험할지
- R4 판정을 누가 할지(사용자 직접 / 가족·지인 시험 참여자)
